# Documentation

- `design/` is the canonical game design: what the player does, who the story follows, and what
  the project will actually ship.
- `architecture.md` defines the implementation boundaries that protect that design.
- `canon-boundary.md` separates inherited Glass Frontier facts from Homeomorph proposals.
- `backlog.md` records the ordered path from scaffold to finished game.
- `adr/` records durable technical and production decisions.

Documents describe the current decision, not a diary of abandoned versions. When a decision
changes, update the owning document and add an ADR only when future contributors need to know why
the architectural constraint exists.
